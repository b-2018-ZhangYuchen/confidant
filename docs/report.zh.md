# Confidant：让本地小模型做有证据支撑的约会红旗检测

张宇晨 — GenAI 课程项目报告（草稿）

> 英文版：[report.md](report.md)。每个数字都能在 `experiments/` 里找到对应的保存记录，
> 各步骤的详细说明在 [`docs/lab/`](lab/)（英文）。

## 1. 问题

Confidant 读一段约会软件上的聊天记录，给出谨慎的第二意见。它的红旗检测会指出令人担忧的行为
（威胁、胁迫、监控、经济施压等共 12 类），分三个等级（watch / concern / danger），并附上
**原文引用**作为证据。系统在代码层面保证三件事：

- 每条引用都会和聊天记录逐字比对，对不上就丢弃；
- 危险类别永远不会被降级到 danger 以下；
- 不允许使用诊断标签（如“自恋型人格”），见 `docs/principles.md`。

此前这项检测调用 Claude API。本项目要回答的问题是：**一个能在学生笔记本上运行的开源小模型，
经过定制后，能不能做同样的事？**如果能，就得到 API 给不了的两样东西：**聊天记录不离开本机**，
以及**每次检测零成本**。工作按课程的八个步骤进行。

## 2. 模型选择（第 1 步）

在 M3 Pro（18 GB）上，把 7 个 4-bit 指令模型（Llama 3.2 1B/3B、Qwen2.5 1.5B/3B/7B、
Qwen3 4B、Mistral 7B）放进真实的红旗检测流程里跑。

- 3B 以下的模型都无法稳定输出规定的 JSON 格式。
- **Qwen2.5-3B-Instruct** 是每次都能按格式回答的最小模型，也是其中最快的（每次 3.8 秒，
  内存 2.8 GB），被选为定制对象。
- **Qwen3-4B** 开箱效果最好，保留作对照。
- **Qwen2.5-7B** 用来生成训练数据。

→ [lab/model-selection.md](lab/model-selection.md)

## 3. 数据准备（第 2 步）

项目不能使用任何真实聊天记录，所以带标签的数据只能是合成的：

- **场景表：**100 个手写场景。55 个埋入红旗（每类 5 个），25 个是“看起来像红旗但其实不是”的
  困难负例（比如“到家了给我发个消息报平安？”），20 个是完全正常的聊天。
- **生成：**每个场景由 7B 模型写三遍，名字、长度、语气各不相同。
- **标签按构造保证正确。**模型只写埋点句周围的对话，埋点句由代码插入。最初让模型自己把句子
  写进去，11 段里只能留下 1 段；改成代码插入后，303 段留下 300 段。
- **按场景划分数据集**（180/60/60），保证测试场景的任何改写都不会出现在训练里。另有污染检查，
  确保 9 个手写金标准案例不出现在任何数据中。
- **继续预训练语料：**6,107 篇文档（约 94.7 万词），来自 DailyDialog、EmpatheticDialogues、
  Synthetic-Persona-Chat 和 13 篇关于虐待与诈骗的维基百科条目。已脱敏，并整理成红旗提示词里
  展示聊天的格式。

→ [lab/data.md](lab/data.md)

## 4. 基线（第 3 步）

用 Confidant 自己的提示词，未修改的 3B 模型每次都能按格式回答，但**每次都说没有问题，而且
信心很高**，包括对方明确威胁人的时候。验证集和测试集上 **F1 为 0.00，33 个危险案例全部漏掉**。
开箱即用时，它恰好给出 Confidant 最要避免的那种虚假安慰。

## 5. 定制（第 4 步）

尝试了四类方法，单独使用也组合使用：

| 方法 | 效果（验证集） |
|---|---|
| 提示词：精简格式 | token 更少，但格式有效率从 100% 降到 80% |
| 提示词：few-shot（2 个训练样例） | F1 0.00 → 0.47，无误报 |
| RAG：模式卡片，逐句 BM25 检索 | 单独用没有变化；加在微调模型上：类别 F1 0.42 → 0.56，危险漏报 10 → 6（共 18） |
| 继续预训练（QLoRA，约 40 万 token） | 对话困惑度 5.75 → 3.98，但有效 JSON 从 80% 降到 13%（灾难性遗忘） |
| 微调（QLoRA r=8，180 条样本，2 个 epoch） | 选定检查点 F1 0.81 |
| 引用修复（拆开把多条完整消息拼在一起的引用） | 最终适配器：F1 0.47 → 0.57，引用核验通过率 67% → 87% |

两个发现决定了后面所有的选择：

1. **验证损失选错了检查点。**损失最低的检查点（第 100 步）什么都不标。超过 40% 的标准答案是
   “无红旗”，这是最容易学的输出，所以模型处处说“没问题”时损失反而最低。各检查点的 F1：
   第 100 步 0.00，第 200 步 0.17，**第 300 步 0.81**，第 360 步 0.57。之后所有选择都按验证集
   F1 来做。
2. **拼接引用。**微调模型找对了句子，但把相邻两条消息当成一条来引用。引用核验正确地拒绝了它，
   因为拼起来的引用可能说出两条消息各自都没说的意思。修复只在引用**恰好**是若干条完整消息相连
   时才拆分，所以每条引用仍然是逐字原文。

→ [lab/experiments.md](lab/experiments.md)

## 6. 参数实验（第 5 步）

- **学习率：**2e-4 发散（验证损失 0.70 → 1.81，输出退化）。5e-5 以及 rank 4 和 16 只跑了
  150 步，都还停留在“什么都不标”的阶段。训练长度的影响压倒一切，短实验分不出 rank 的差别，
  这是本实验最大的缺口。
- **温度：**0.3 和贪心解码持平。0.7 改善了严重程度判断，但困难负例的误报翻倍。top-p 0.9
  所有指标都更差。最终保留贪心解码，因为它结果确定、可复现。
- **上下文：**只给最后 8 条或 14 条消息，F1 降到 0.42 和 0.53，因为证据也被截掉了。长聊天
  需要分窗处理，而不是截断。
- **检索：**逐句 BM25（k=3 时召回 58%）好于 MiniLM（45%）和 BGE-small（48%）向量检索。
  埋点句和卡片用词相近，而逐句打分能避免闲聊把真正关键的那一句淹没。

## 7. 对比评估（第 6 步）：测试集，未见过的场景

| 系统 | F1 | 危险漏报 | 金标准 | 秒/次 |
|---|---:|---:|---:|---:|
| Qwen2.5-3B 原版 | 0.00 | 15/15 | 64% | 3.6 |
| Qwen2.5-3B + few-shot | 0.30 | 12/15 | 72% | 4.3 |
| Qwen3-4B 原版 | 0.42 | 14/15 | 83% | 6.5 |
| 继续预训练 → 微调 | 0.43 | 9/15 | 61% | 3.5 |
| **微调 + 引用修复** | **0.78** | **4/15** | **92%** | 3.9 |
| **微调 + 引用修复 + RAG** | 0.75 | **4/15** | 89% | 4.5 |
| Claude | 需要 API key，见路线图 | | | |

微调后的 3B 模型在每项指标上都超过开箱的 Qwen3-4B，延迟只有它的 0.6 倍。RAG 用 0.03 的 F1
换来更准的类别（0.34 → 0.46），并消除了困难负例上的误报。所有系统都没有使用诊断标签。

## 8. 消融与错误分析（第 7 步）

在测试集上，从完整系统中每次去掉一个组件：

- **去掉微调：**F1 −0.45（与 few-shot 相比）。
- **去掉检查点选择：**−0.28。
- **去掉 RAG：**F1 +0.03，但类别 F1 −0.12。
- **去掉引用核验：**F1 +0.04。测试集上被它丢弃的每一条，都是对真实句子的近似误引，核验拒绝
  它们是对的。
- **去掉引用修复：**测试集上无影响（选定的检查点很少拼接引用）。
- **加上继续预训练：**−0.32。

真正要紧的错误：

1. **危险行为被归到非危险类别。**一条威胁被归为“回避”，就绕过了按类别生效的危险等级下限。
2. **表面用词过度泛化。**“我保证野餐后跟你分享一个秘密”被标成危险级威胁，因为训练里有一个
   威胁要分享私密照片的场景。
3. **言外之意。**“你知道那是什么意思”每次都被漏掉。

对应的修法：危险类别二次复核；构造复用每个危险场景自身用词的困难负例；需要理解言外之意时，
默认仍用 Claude。

## 9. 外部测试：MentalManip 与 ReaMent

以上数据都出自同一个生成器。为了检验这掩盖了什么，同样的系统在
[MentalManip](https://github.com/audreycs/MentalManip)（ACL 2024，CC BY-NC 4.0）的 120 段
对话上运行。这些是人写的电影对白，三位标注员一致标为“操纵”或“非操纵”。一半是操纵性的，
覆盖全部 11 种手法。因为数据没有说明谁在操纵，每段对话分别以两位说话人作为“对方”各测一次。

| 系统 | F1 | 召回 | 误报（任意 / concern 及以上） | 类别一致率 |
|---|---:|---:|---:|---:|
| Qwen2.5-3B 原版 | 0.00 | 0.00 | 0 / 0（共 60） | — |
| + few-shot | 0.67 | 0.65 | 18 / 16 | 0.51 |
| Qwen3-4B 原版 | 0.66 | 0.70 | 25 / 20 | 0.50 |
| 微调 + 引用修复 | **0.74** | **0.93** | 35 / 14 | 0.39 |
| 微调 + 引用修复 + RAG | **0.74** | 0.88 | 31 / 13 | 0.47 |

- **微调模型仍是最好的检测器，但对 Qwen3-4B 的领先**从 0.36 F1 缩小到 0.08。合成数据上的
  一部分优势，来自学会了生成器的写法。
- **它在人写的对话上标得太多。**58% 的非操纵对话被标出红旗，而合成的正常聊天只有 17%。大多是
  对简短回复标 watch 级“回避”，这是从合成的回避场景里学来的习惯。
- **每个系统都在非操纵对话上给出过危险级红旗。**微调模型的这类红旗中，约四分之一是惊悚片情节
  里真实的威胁，其余是错误。
- **RAG 提高了类别一致率**，与合成测试集上的方向一致。

**ReaMent**（WWW 2026，CC BY-NC-ND 4.0）用同样的标签，但对象是从网络视频转录的**即兴、
非剧本**口语，是本项目能拿到的最接近真实对话的数据。同样 60 + 60 的协议：

| 系统 | F1 | 精确率 | 召回 | 误报（任意 / 危险级） |
|---|---:|---:|---:|---:|
| + few-shot | **0.71** | 0.66 | 0.77 | 24 / 21 |
| Qwen3-4B 原版 | 0.65 | **0.67** | 0.63 | **19 / 3** |
| 微调 + 引用修复 | 0.67 | 0.52 | **0.93** | 52 / 12 |
| 微调 + 引用修复 + 卡片 | 0.70 | 0.57 | 0.92 | 42 / 10 |

在真实口语上，**微调模型不再领先。**离合成数据每远一步，它的精确率就下降一截
（0.88 → 0.62 → 0.52），召回却始终是 0.93。它学到的是：在对方的话里**总能找出点什么**。

→ [lab/external.md](lab/external.md)

## 10. 基于恋爱指导材料的 RAG

模式卡片是我自己写的，而且从 11 张里挑 2 张算不上真正的检索。所以 RAG 改为在真实的
恋爱关系指导语料上重建：39 个网页（美国政府健康网站，公有领域；24 篇维基百科条目，
CC BY-SA），约 11.6 万词。wikiHow 原本在计划内，因为它屏蔽了 Anthropic 的爬虫而放弃。

- **验证集网格实验**（切块方式 × 检索器 × k）：向量检索优于 BM25；检索段落越多，模型越谨慎。
  按段落切块 + MiniLM + k=4 得到 F1 0.80，精确率 1.00。
- **合成测试集：**所有系统中危险召回最好（15 个只漏 2 个，原来漏 4 个），F1 也最高（0.79）。
- **外部数据：**没有解决误报。ReaMent 上误报从 87% 降到 78%，而卡片能降到 70%。危险级误报
  反而从 12 升到 15。
- **一个被检验并推翻的解释：**语料中 46% 是关于虐待的材料，看起来像是原因。但只从普通关系
  段落中检索后，危险级误报**更多**了（18）。任何检索文本都会把这个微调模型推向危险判断，
  最可能的原因是它训练时的提示词里没有检索内容。

→ [lab/guidance.md](lab/guidance.md)

## 11. 可复现性（第 8 步）

- **代码：**全部在 `confidant.lab` 中（`python -m confidant.lab --help`），放在 `lab` 可选
  依赖之后，测试可离线运行：核心测试套件不依赖它。
- **配置：**每次训练都是 `experiments/configs/` 里的一个 YAML 文件。
- **记录：**每次评估都保存配置、完整命令行、每条模型原始回答和分数。
  `python -m confidant.lab reproduce <run>` 会在原记录旁重跑（已验证 60/60 完全一致）；
  `rescore` 不调用模型，用不同的检查规则重放已保存的回答。
- **提交到仓库的内容：**生成的数据集、场景表和模式卡片。模型、适配器和下载的语料都由脚本重建。
- **模型卡：**[lab/model-card.md](lab/model-card.md)。

## 12. 结论

一个 670 万参数的适配器，用 180 条合成样本在笔记本上训练 42 分钟，就把一个什么都看不出的
3B 模型，变成了能在未见过的场景中抓到 70% 埋点红旗的模型，并通过 92% 的手写金标准检查。
它的错误也恰好落在这个工具最在意的地方：四分之一的危险案例没有被归为危险。

在任务之外、人写的对话上，它的领先缩小了：电影对白上只剩 0.08 F1，真实即兴口语上则完全消失。
在那里它把 87% 的普通对话标出红旗（大多是 watch 级），而开箱的 Qwen3-4B 校准得好得多。

因此，本地模型是 Claude 之外一个可信的**隐私选项**，而不是替代品：不愿把聊天发到任何地方的
用户，也能得到一次真正的检查，并保留同样的引用核验和安全下限。

## 13. 目前的问题

按严重程度排列：

1. **真实对话上误报太多（最核心）。**训练数据中 55% 的对话埋了红旗，而且红旗全在对方的话里，
   模型因此学会了“总能找出点什么”。真实对话里充满含糊、短回复、跑题和改口，被它当成“回避”
   和“前后不一”。
2. **危险级误报会错误地弹出安全提示。**ReaMent 上微调模型有 12 次（加 guidance RAG 后 15 次），
   开箱的 Qwen3-4B 只有 3 次。典型错误包括把“Wow, you are smart”归为性施压，以及把转述
   别人的威胁（“他说如果我……”）当成说话人自己的威胁。本地模型的危险级判断不能单独触发
   安全提示。
3. **合成数据高估了效果。**相对 Qwen3-4B 的优势从 0.36 F1（合成）到 0.08（电影对白）再到
   负数（真实口语）。全部训练数据出自一个 Qwen2.5-7B，与被训练模型同一家族。
4. **RAG 没有解决误报。**推测原因是训练时没见过检索文本，这一点尚未验证。
5. **实验本身的局限：**
   - 测试集小：一个场景约等于 9 个百分点的召回；
   - 每个配置只跑了一次（seed 0），没有置信区间；
   - 负例标签尚未经过人工审核（计划抽查 50 条）；
   - 继续预训练在本设置下是负收益（−0.32 F1）；
   - 缺少 Claude 对照组（没有 API key）。
